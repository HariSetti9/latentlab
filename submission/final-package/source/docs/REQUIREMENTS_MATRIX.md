# Requirements Matrix

This matrix is derived from all 20 pages of `DataForge_Pathway_Codex_Astra_Master_Prompt.pdf`.

| Area | Mandatory result | Verification |
|---|---|---|
| Claim | Preserve the exact two-clause falsifiable claim, including the non-guarantee | Charter, learner copy, results, PDFs agree |
| Learner | Average data scientist / ML student with vector, NN, and high-level Transformer knowledge | Product spec and learning test |
| Computation | Fixed-size state receives N real recurrent updates without generated chain-of-thought | Unit tests and live control trace |
| Truth | Independent transparent deterministic solver beside every correctness-dependent estimate | Dependency separation test and UI |
| Observable state | Honest task-relevant channel/projection, iteration, prediction, error, and justified metrics | Definitions in UI and model card |
| Limitation | Empirically real saturation/oscillation/interference case; never manufactured | Fixed fixture and evaluation output |
| Research | At least three verified 2022-2026 primary papers plus BDH/BDH-CQ primary sources | Source dossier and claims ledger |
| BDH/BDH-CQ | First-class in-flow module; direct vs adjacent vs not-equivalent; published vs own evidence | Notes, comparison table, citation audit |
| Journey | Guide -> Experiment -> Observe -> Compare -> Challenge -> Explain; default live preset; sandbox after guidance | Product spec and 60-second E2E |
| UX | Fast, restrained research-explainer aesthetic; few meaningful controls; loading/error/default states | Screenshots and UX audit |
| Accessibility | Keyboard, visible focus, contrast, responsive type, reduced motion, text alternatives, no color-only meaning | Automated/manual audit |
| Performance | Ordinary controls under one second when practical and measured honestly | Benchmark protocol and QA record |
| Testing | Core recurrence, solver, determinism, boundaries, invalid input, wiring, E2E, mobile, failure states, build/lint/type-check | CI and local reports |
| Reproducibility | Dataset/seed/script/weights metadata if trained; fixed evaluation; checksums; clean setup | Reproduction test and docs |
| Provenance | Code/data/weights/assets/fonts/reuse, AI assistance, licenses, credits | Provenance files and notices |
| Documentation | Complete README, blog PDF, one-page summary PDF, model card, protocol, results, quickstart | Render/link/content checks |
| Release | No secrets/localhost/unresolved citations; public no-login artifact and public source | Scans and production smoke test |
| Packaging | Demo script, submission checklist/links, clean final tree, deterministic ZIP and SHA-256 | Archive listing and checksum |

## Phase dependencies

`Phase 0 contract` -> `Phase 1 verified evidence` -> `Phase 2 learning design` -> `Phase 3 substrate` -> `Phase 4 web artifact` -> `Phase 5 BDH copy audit` -> `Phase 6 evaluation` -> `Phase 7 submission documents` -> `Phase 8 red-team QA` -> `Phase 9 publication` -> `Phase 10 package`.

Research gates scientific copy; product design gates UI; the computational substrate gates visual polish; evaluation gates result claims; QA gates deployment; verified public links gate the final archive.

## Mandatory deliverables

1. Public no-sign-in interactive artifact.
2. Public source repository.
3. README with deliverable links and all specified sections/disclosures.
4. Blog source and rendered PDF.
5. One-page concept-summary source and rendered PDF.
6. Three or more recent primary papers and verified BDH/BDH-CQ sources.
7. Claims/evidence ledger, paper notes, landscape, and BDH notes.
8. Real substrate, independent solver, scripts, tests, fixtures, model card, metrics, checksums, protocol, results.
9. Source/license record, provenance, third-party notices as needed, and AI disclosure.
10. Desktop/mobile QA evidence, learning-test protocol, scorecard, and judge audit.
11. Deployment configuration and CI.
12. Demo script/shot list and final-links sheet.
13. Final clean submission directory, deterministic ZIP, manifest, and SHA-256.
14. Exact manual actions for video upload and Unstop submission where automation/authorization is unavailable.

## Judging implementation strategy

- **25 technical:** source every claim; keep solver/model independent; define every metric; ship repeatable item-level evaluation and limitations.
- **15 ownership:** compact architecture, decision records, model card, readable code, and a judge quickstart.
- **15 learning:** default preset, single causal control, visible truth, guided failure, self-check, and tested 60-second flow.
- **15 interaction/honesty:** live local recurrence, direct state inspection, explicit evidence labels, and no decorative telemetry.
- **10 BDH:** primary-sourced in-flow comparison that states analogy and non-equivalence precisely.
- **10 craft:** responsive accessible design, graceful failures, lean build, stable deployment, and complete provenance.
- **10 summary:** a rendered, readable, evidence-dense one-page PDF checked visually.
