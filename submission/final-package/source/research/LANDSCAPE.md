# Recurrent and Continuous Latent Reasoning Landscape

This comparison is intentionally mechanism-level. It does not rank systems and does not imply equivalence.

| Approach | Computation representation | Memory/state growth | Test-time compute mechanism | Observability | Cost/latency implication | Evidence maturity |
|---|---|---|---|---|---|---|
| Explicit token reasoning (baseline concept) | Discrete generated tokens | Visible sequence/context grows with emitted tokens | Generate additional intermediate tokens, sometimes sample/verify alternatives | Text is inspectable but is not guaranteed to be a faithful internal account | More generated tokens generally add sequential decoding work and context | Broad literature; no single benchmark claim used here |
| Recurrent-depth model (Geiping et al., S1) | Repeated hidden representations inside a shared block | Hidden width fixed; depth unroll count changes | Repeat a recurrent block at inference | Hidden states can be analyzed but are not natural-language steps | Additional recurrent passes add computation without requiring extra reasoning-token output | 2025 primary paper; author-reported large-scale experiments and released artifacts |
| Coconut (Hao et al., S2) | Last hidden state reused as a continuous input representation | Adds continuous-thought positions/steps rather than verbalized steps | Feed continuous thought back for subsequent processing | Latent vectors are less directly interpretable than text | Replaces some intermediate token decoding with continuous-state processing; exact trade-offs are task/system-specific | 2024/2025 primary paper; author-reported experiments |
| BDH base architecture (Kosowski et al., S3) | Learned graph/state-space dynamics of locally interacting units | Authors describe inference working memory through synaptic plasticity | Base paper focuses architecture/sequence learning; do not equate it automatically with a user-set reasoning-depth loop | Authors report sparse positive activations and interpretability properties | Hardware/efficiency claims require detailed paper-level qualification before use | 2025 primary developer paper; no independent reproduction recorded here |
| BDH-CQ (Engdahl et al., S4) | Learned recurrent memory and high-dimensional latent computation | Demonstrations update recurrent memory; query reasoning is iterative | Recurrent latent updates before answer decoding | Paper studies learned transformations/concepts; our project does not reproduce its probes | Paper reports a computed ARC-AGI-1 cost point; not reproduced here | 2026 primary developer paper; author-reported evaluation |
| LATENTLAB toy | Transparent task-specific grid state | Fixed grid state; iteration trace may be retained only for display | Deterministic local propagation repeated N times | Every cell value and derived metric is inspectable | Tiny browser workload; latency will be measured rather than assumed | Our reproducible educational experiment, not a language model |

## Design consequence

The experience will use recurrent depth as the manipulated variable because it is the cleanest way to isolate the central claim. Coconut demonstrates that another latent-feedback mechanism exists; BDH supplies the architecture context; BDH-CQ supplies the mandatory direct connection to recurrent latent query computation. None is presented as interchangeable with the toy.
